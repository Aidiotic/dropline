Roadmap

Ordered by how much each one actually hurts today. The first is the only thing left that makes transfers fail outright, and it is waiting on an account credential rather than on code.

  1. TURN relay blocked

    Still the biggest gap: roughly 10–20% of network pairs cannot form a direct connection and those transfers fail outright. The worker is deployed at dropline-turn.dropline.workers.dev and the client is wired to read short-lived credentials from it, but no TURN key has been created in the Cloudflare dashboard, so it answers 404 and the app falls back to STUN. Creating that key means handling an API token, which is the account owner's to do.

  2. Resume an interrupted transfer

    A dropped connection recovers the session, but the file in flight restarts from zero.

  3. More than two devices

    A session holds exactly one pair; two recipients means two links.

  4. Verify on real iOS and Firefox

    Every automated check runs in one Chromium browser. The Safari and Firefox fallbacks are exercised by simulating a missing API, which proves the fallback code but is not the same as running there.

Releases

v1.4 23 Aug 2026

  • Compression is decided by measurement, not by the file's name. The old rule guessed from the declared type, and it was wrong in both directions: a .bin that was already an archive got compressed for nothing, and a .dat full of plain text was sent raw. A quarter-megabyte sample is now compressed first and the real ratio decides, with anything that only shaves a few percent left alone — that CPU is paid on both ends, and on a weak device it is the difference between smooth and stuttering.
  • The sample is taken a quarter of the way in rather than from the front, because containers put headers and metadata at the start and those compress quite unlike the payload behind them.
  • A type already known to be packed still skips straight past without paying for a measurement at all.

v1.3 23 Aug 2026

  • Five performance tiers rather than three, so a 2 GB dual-core and a 24-core workstation no longer share a budget — from a single data channel and 32 KB chunks at the bottom to six channels and 16 MB buffers at the top.
  • The tier is measured, not assumed. navigator.deviceMemory is coarse and may be clamped, so it cannot tell those two machines apart. Alongside it the browser now times real work — a checksum over a megabyte, a couple of milliseconds — and where the spec sheet and the stopwatch disagree, the stopwatch wins. A machine claiming 8 GB that processes bytes slowly is demoted. Taken as the best of three rounds, because one cold pass in a background tab made a fast machine look slow.
  • A settings sheet for theme, motion, performance and auto-accept, showing what was detected including the measured figure. Choices survive a reload and are re-asserted after the device profile recomputes, which writes the same attributes.
  • Auto-accept was in two places at once; it is a setting, so the main view is three plain verbs again. Copy trimmed throughout.
  • There is a theme that is not in the list.

Multi-file batches were arriving with only the first file intact: the receiver restarts its per-channel counts at every item, but the sender kept its round-robin position across the whole batch, so the second file began on the wrong channel. The integrity checking is what surfaced it — those files failed loudly rather than arriving quietly corrupted.

v1.2 23 Aug 2026

  • Transfers are 49% faster — 8.7 MB/s to 13 MB/s on the same measurement, byte-for-byte verified. Three separate causes:
  • PeerJS was running its default binary serialization, which packs every message and then re-splits it into 16 KB pieces, undoing the negotiated 256 KB chunk size. Switching to raw removes an encode and decode pass per chunk.
  • The uncompressed path no longer builds a stream, re-chunks it and copies each piece. Slicing the file directly yields buffers that are already exactly one chunk and already ours, so they reach the wire untouched, and reads run one chunk ahead so disk and network overlap.
  • The payload is striped across parallel data channels. A raw channel carrying no application logic measured the same 10.5 MB/s as dropline did, so the engine was already at the SCTP ceiling and the only way past it was more channels — measured 14.1 on two, 15.0 on four, 16.0 on eight. Ordering needs no per-chunk header: chunk i goes to channel i mod N and each channel is ordered on its own, so the k-th arrival on channel c is globally chunk k·N+c.
  • The interface adapts to the device. Memory, cores, network type, data-saver, battery, pointer and viewport are scored into a tier, and that drives chunk size, seal interval, receive watermark, repaint rate, thumbnails and how much it animates — so a cheap phone on a dying battery does less work rather than the same work more slowly. Recomputed on resize, rotation, network and battery changes.
  • Sessions are authenticated. The link carries a secret after ~; fragments are never sent to a server, so the signalling broker learns the session id and nothing else. Both ends prove they hold it before any transfer is accepted, and a four-character code is shown on both devices to compare. Links without a secret still work and say plainly that they are unverified.
  • Installable, with an offline shell. Caching a static site is normally how stale code gets served — safe here only because the build fingerprints its own output, so those files are immutable by construction while HTML and config stay network-first.
  • Connection quality is shown: direct or relayed, with round-trip time.

Four bugs surfaced building this. The worst: PeerJS's negotiator claims any arriving data channel as its own connection's, so every stripe re-initialised the session, regenerated the authentication nonce and left control messages on the wrong channel. Fixing it needed the platform's internal handler slot cleared, not merely the JavaScript property overridden.

v1.1 23 Aug 2026

  • The interface was stripped back. Boxes and filled buttons are gone; actions are text with an underline that draws on hover, inputs are a single hairline, and hierarchy comes from whitespace and weight rather than borders.
  • The orange square is now the state, not decoration. It breathes while waiting, tumbles while connecting, settles once on connect, and pulses an outward echo while bytes are moving. One attribute drives all of it — and every state is still written in words, so nothing depends on seeing the motion.
  • Files are checksummed end to end. A rolling CRC32 is computed as the file streams — before compression on the way out, after decompression on the way in — and compared on arrival. A mismatch fails the transfer visibly and refuses to offer the file for download. This targets the exact bug that shipped in v0.3, where reordered chunks corrupted a file with nothing on screen to suggest anything was wrong.
  • The screen is held awake during a transfer and released the moment it finishes — the difference between a phone finishing a large file and sleeping halfway through.
  • Drop anywhere on the page, not just onto the box. Received images get a thumbnail. The tab title shows transfer progress. Native share sheet where the browser has one. An auto-accept toggle, and Escape to decline.
  • Transfer rates are smoothed. A running total-over- elapsed average reports a figure from half a minute ago and jitters badly at the start; an exponential moving average tracks what the link is actually doing.
  • 51 unit tests, including the canonical CRC-32 check vector.

v1.0 23 Aug 2026

  • Both devices can send. A session is now symmetric rather than one sender and one receiver — either side can push files at any time, with the same interface on both.
  • Multiple files and whole folders. Drag a folder in, pick several files, or paste a screenshot straight into the page. Folder structure is rebuilt on the far side; every path segment is sanitised on both ends so a sender cannot write outside the directory you chose.
  • Text and link snippets without making a file first, with one-tap copy at the other end.
  • Reconnects instead of dying. A dropped connection retries with backoff, and the session survives a phone locking or a tab being backgrounded. The file that was in flight restarts.
  • Accessibility pass. Live-region announcements for state changes, progress bars exposing aria-valuenow, keyboard-reachable drop zone, and touch targets that stay comfortable on a phone.
  • Assets are content-hashed. Filenames change when the contents change, so the ten-minute Pages cache can no longer serve stale code — and nobody has to remember to bump a version.
  • 42 unit tests over the pure logic, run in CI along with a check that the committed build matches src/.
  • Configurable ICE servers, TURN endpoint and signalling host via config.js.

v0.9 23 Aug 2026

  • Replaced the download service worker with Blob sealing. Chunks are sealed into Blobs every few megabytes; browsers spill those to disk, so the heap stays flat without a worker. The finished file is offered as an ordinary download link — a real click, which browsers treat far more permissively than a synthetic download.
  • Seal interval adapts to navigator.deviceMemory: 2 MB on low-memory devices, 8 MB on capable ones.

This approach is lifted from Beam, a LAN QR-transfer app, which solved the same problem more robustly than the worker did.

v0.8 22 Aug 2026

  • Stopped claiming files were saved when they weren't. The receiver announced success as soon as it finished pushing bytes, which is upstream of the browser actually writing the file. Chrome was observed silently refusing a download while the interface said it had been saved — the worst possible failure, since you'd never think to ask for it again.

v0.7 22 Aug 2026

  • Added flow control between the two peers. A 64 MB transfer was measured growing the receiver's heap by 118 MB, so the earlier claim of flat memory was simply wrong. Backpressure existed between the page and the worker, but nothing throttled the data channel filling the queue, so the backlog moved upstream instead of going away.
  • The receiver now queues by byte length against a 4 MB watermark and sends hold/go over the data channel. Peak growth for the same transfer fell to 55 MB, and doubling the file to 128 MB added only 22 MB more.

v0.6 22 Aug 2026

  • Streamed downloads through a service worker so browsers without the File System Access API stopped assembling whole files in memory. Superseded by v0.9.

v0.5 22 Aug 2026

  • Fixed buttons that ignored the hidden attribute. .btn sets display: block, which outranks the browser's own [hidden] { display: none }. A Download button was visible before anything had been received.
  • Asset URLs versioned, so returning visitors stopped running stale code against fresh markup. Replaced by content hashing in v1.0.

v0.4 22 Aug 2026

  • Opening a second link in an open tab did nothing. Only the hash changes, which doesn't reload the page, so the receiver kept showing the previous sender's file and a spent accept button.

v0.3 22 Aug 2026

  • Fixed out-of-order corruption. The receiver's message handler was async, so when a chunk arrived as a Blob the pause let a later chunk be written ahead of an earlier one. Messages now run through a promise chain.

v0.2 22 Aug 2026

  • Rebuilt the interface: flat, cream and ink, one clay accent.
  • The file is streamed rather than buffered, chunk size is negotiated from the connection's maxMessageSize instead of hard-coded at 64 KB, and compressible files are gzipped in flight.
  • QR code, so a phone can scan the link instead of typing it.

v0.1 22 Aug 2026

  • First version. Peer-to-peer file transfer over WebRTC, hosted as a static page, with no server holding the file at any point.
