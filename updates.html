Roadmap

Ordered by how much each one actually hurts today. The first two are the difference between a demo and something you'd rely on.

  1. TURN relay next

    Roughly 10–20% of network pairs — two symmetric NATs, or a strict corporate firewall — cannot form a direct connection at all, and today those transfers simply fail. A TURN relay is the only real fix. This is the single biggest gap.

  2. Self-hosted signalling next

    Introductions currently go through PeerJS's free public broker: a shared service with no uptime guarantee, and the most likely thing to break without warning. Moving it to a Worker removes the one third-party dependency in the path.

  3. Multi-file and folders

    One file per link today; a folder means zipping it first. A queue, with drag-and-drop and paste-a-screenshot, covers what people actually want to send.

  4. Reconnect after sleep

    If a phone locks or backgrounds the tab mid-transfer, the connection dies and the whole file starts over. Rescanning the same code should resume instead.

  5. Send in both directions

    The sender is whoever opened the page first. Either side should be able to send, with the same interface on both.

  6. Text and link snippets

    Sending a URL, a wifi password or a snippet of code shouldn't require making a file first.

  7. Accessibility pass

    Focus rings and keyboard access exist; live-region announcements and progress bars that expose aria-valuenow do not.

Releases

v0.9 23 Aug 2026

  • Replaced the download service worker with Blob sealing. Chunks are sealed into Blobs every few megabytes; browsers spill those to disk, so the heap stays flat without a worker. The finished file is offered as an ordinary download link — a real click, which browsers treat far more permissively than a synthetic download.
  • Seal interval adapts to navigator.deviceMemory: 2 MB on low-memory devices, 8 MB on capable ones.
  • Any previously registered service worker is now unregistered on load.

This approach is lifted from Beam, a LAN QR-transfer app, which solved the same problem more robustly than the worker did.

v0.8 22 Aug 2026

  • Stopped claiming files were saved when they weren't. The receiver announced success as soon as it finished pushing bytes, which is upstream of the browser actually writing the file. Chrome was observed silently refusing a download while the interface said it had been saved — the worst possible failure, since you'd never think to ask for it again.

v0.7 22 Aug 2026

  • Added flow control between the two peers. A 64 MB transfer was measured growing the receiver's heap by 118 MB, so the earlier claim of flat memory was simply wrong. Backpressure existed between the page and the worker, but nothing throttled the data channel filling the queue, so the backlog moved upstream instead of going away.
  • The receiver now queues by byte length against a 4 MB watermark and sends hold/go over the data channel. Peak growth for the same transfer fell to 55 MB, and doubling the file to 128 MB added only 22 MB more.

v0.6 22 Aug 2026

  • Streamed downloads through a service worker so browsers without the File System Access API stopped assembling whole files in memory. Superseded by v0.9.

v0.5 22 Aug 2026

  • Fixed buttons that ignored the hidden attribute. .btn sets display: block, which outranks the browser's own [hidden] { display: none }. A Download button was visible before anything had been received.
  • Asset URLs are versioned. GitHub Pages serves files with a ten-minute cache, so returning visitors were running stale code against fresh markup.

v0.4 22 Aug 2026

  • Opening a second link in an open tab did nothing. Only the hash changes, which doesn't reload the page, so the receiver kept showing the previous sender's file and a spent accept button.

v0.3 22 Aug 2026

  • Fixed out-of-order corruption. The receiver's message handler was async, so when a chunk arrived as a Blob the pause let a later chunk be written ahead of an earlier one. Messages now run through a promise chain.

v0.2 22 Aug 2026

  • Rebuilt the interface: flat, cream and ink, one clay accent.
  • The file is streamed rather than buffered, chunk size is negotiated from the connection's maxMessageSize instead of hard-coded at 64 KB, and compressible files are gzipped in flight. Already-packed formats skip compression.
  • QR code, so a phone can scan the link instead of typing it.

v0.1 22 Aug 2026

  • First version. Peer-to-peer file transfer over WebRTC, hosted as a static page, with no server holding the file at any point.
